`docs/ai/config.md` is the file that steers how the project is worked on. It is a set of Markdown tables, one section per topic. `init` fills in the values from what it asked or detected; you change them any time. Nothing needs a rebuild: the session-start hook reads the file and reports what changed since the last sync. Every key with its allowed values is listed in the [configuration reference](/agentic-coding-template-docs/reference/configuration/); this page explains what the groups are for. `/act-config` shows and sets these values without a model turn, see [Changing the file](#changing-the-file).

## Groups

- **Project**: name, owner, `language-chat` and `language-docs`, `stack`, the lint/typecheck/test `commands` (optionally a fourth for the full or E2E suite, run before a push), the `tools` you use and the `mode` (`solo` or `team`, see [Work entries](/agentic-coding-template-docs/concepts/work-entries/)). `language-chat` is the language the assistant talks to you in (`auto` follows your messages); `language-docs` is the language of everything it writes under `docs/`. `.act/` stays English either way. A command set to `(not set)` skips the matching check before a commit. `run` is the command that starts the application; `(not set)` means none is recorded.
- **Scope**: `profile` (`minimal`, `standard` or `full`; a missing key counts as `full`; `init` writes `full` for a web project and `standard` for any other, `--scope` decides otherwise, and `update` never changes it) and `exclude` (`none` or a comma-separated list) trim the template per project: `standard` leaves out the web, design and teaching skills, `minimal` keeps only the core skills and roles, and `exclude` names single skills, roles, rule files such as `orchestrator/30-cost.md`, or topics on top. The session start removes the copies of what is left out, switches the import line of an excluded rule file in `docs/ai/rules.md` to a bare path (Claude Code stops loading it) and says so in one line; a change takes effect from the next session. `shared/10-safety.md` cannot be excluded, and the checks stay on either way. To undo it, set `profile` to `full` and `exclude` to `none`. `methods` (`none` by default, or a comma-separated list of `test-first`, `spec-first` and `simple-changes`) switches on working methods: rule sets for how the assistant works, from `.act/methods/` or your own in `docs/ai/local/methods/`. The session start, `act-update` and `python .act/scripts/rules.py --sync-methods` write each named method into `docs/project/coding_rules.md` as an imported set, so the orchestrator and every worker load it, and a single group can be unchecked there; `init` asks once and `act-doctor` reports a name without a file or a section that no longer matches the row. The skill and role lists are in the [configuration reference](/agentic-coding-template-docs/reference/configuration/#scope).
- **Board**: `board` chooses where the generated board goes (`docs`, `shared`, `local`); `board-others` toggles the section for tasks assigned to other people.
- **Inbox**: `inbox-decisions` decides where an open decision waits. With `immediate` it goes into the inbox as soon as it is booked; with `at-start` a backlog entry may keep it until work on it starts. `quick-capture` (`on` or `off`, default `on`) lets the `UserPromptSubmit` hook file a chat message that begins with `todo:`, `note:` or `idea:` without a model turn, see [Work entries](/agentic-coding-template-docs/concepts/work-entries/).
- **Output depth**: `output-depth` (`verbose`, `normal`, `sparse`) controls how much the assistant writes in chat, not what your tool displays.
- **Session length**: `context-hint` (a token count, default 180000, or `off`) is the context size at which the assistant suggests `/clear` or a new session at the next task boundary. Before it says "now `/clear`", the assistant checks the handover itself (`handover.py`); there is no sentence to copy, and after `/clear` a bare "continue" picks up from the board. `session-name` (`project`, `auto` or any other text, default `project`) sets the Claude Code session title at start, resume and fork: `project` uses the project's `name` (else the folder name), so a Remote Control session on the phone shows which project it is; `auto` leaves it to the tool; other text becomes the title. A title set with `/rename` or `claude -n` is never overwritten. `task-wait-hours` (default 12) is how long a started task may stay quiet before it counts as waiting. `board-at-start` (`on` or `off`, default `on`) adds an excerpt of the board to the session start. `artifacts` (`on` or `off`, default `off`) set to `off` keeps Claude Code from loading the `Artifact` tool, about 13,700 tokens saved per session start.
- **Teaching**: `teach-lessons` (`local`, `docs`) sets where `act-teach` keeps its lessons: `local` under `.act-local/learn/` for you alone, `docs` versioned under `docs/learn/` for the team. The learning record stays local either way.
- **Dependencies** and **Docs audit**: `dependency-check` and `docs-audit-due` control the reminders to run `act-deps` and `act-audit-docs`. New projects get `dependency-check: regularly`: the session start notes once that no `act-deps` run is on record yet, then again whenever the last one is older than 30 days. `once` instead files a single inbox entry after `init`; values already set stay.
- **Update**: `update-channel` (`release` or `latest`, default `release`) chooses what `act-update` brings: `release` only the newest stable release tag of the template source, `latest` the tip of its default branch. The session start announces a new release (on `latest`: a newer tip), and `/act-version` shows three lines (installed, newest in the channel, whether an update is available), `/act-version --all` the full list (`update.py --versions`) with the releases and what an update would take. The announcement is not a one-off: the daily check records it, the session start repeats it at every start, the board lists it under Status and Claude Code's status line shows `update: 2.4.0` (on `latest`: `update: <date>`) until the update is installed. `--versions`, `--plan` and an update run refresh the note or clear it when the project is up to date. `update-check` switches the note off. `init` asks for the value; `act-doctor` reports an invalid one. A source without release tags is followed at its tip, with a note. The daily check's `git ls-remote` allows only the `file`, `git`, `http`, `https` and `ssh` protocols; a source behind another remote helper (such as `ext::`) gets no note at session start, `act-update` itself is unchanged. `advisory-check` (`on` or `off`, default `on`) lets the same daily check ask the template source for warnings about template versions with a known serious problem; those that match your installed version show at session start; `critical` ones also in the status line (`⚠ A<n>`), right below the board title and once as an inbox todo (a todo that was done and deleted is looked up in the git history, read only and within a few seconds, so another workstation does not file it a second time). They stop when an update brings a version outside the affected range, when the files the advisory names no longer hold the faulty text, or when you acknowledge them (say "warning acknowledged", or run `python .act/scripts/advisory.py --ack A<n>`). `off` asks and shows nothing; `update-check: off` stops the lookup too; `advisory.py --status` shows the state. See [Update channel](/agentic-coding-template-docs/getting-started/update/#update-channel).
- **Archive**: `archive-compact` (`<n>d <n>` or `off`, default `30d 300`) says when the session start notes that `act-compact` is due: the oldest entry in the archive or journal folder is older than that many days, or the folder holds more than that many files. `act-compact` only merges, word for word; the former key `archive-shorten` is gone and a value left in a project is passed over. A finished entry is always moved to the archive and nothing leaves `docs/` before it stands in its monthly file. The former key `done-entries` and `entries.py purge` are gone: a leftover `done-entries` row is ignored and the update removes it, and a `purge` call only prints a notice. See [Work entries](/agentic-coding-template-docs/concepts/work-entries/).
- **Formats**: how the assistant words what it writes. `commit-format` (`auto`, `conventional`, `plain`), `changelog-format` (`keep-a-changelog`, `at-release`), `release-notes-format` (`standard`, `changelog-copy`) and `readme-format` (`standard`, `with-toc`, `minimal`) each pick a preset from `.act/formats/`; a file `docs/project/formats/<name>.md` (`commit.md`, `changelog.md`, `release-notes.md`, `project-readme.md`) replaces the template's format for that subject completely and wins over the row. `changelog` (`file`, `release-notes-only`, `off`; default `file`) decides whether the project keeps a `CHANGELOG.md` in its root: `init` creates it with an empty `## [Unreleased]`, `act-update` offers it once to an older project, and neither writes over an existing file or adds a second one next to a changelog under another name. With the default format `act-commit` adds a line under `[Unreleased]` for every commit with a visible effect; `at-release` leaves that to `act-release`. An existing `config.md` has no Formats section until you add it by hand from `.act/skeleton/config.md`. See the [configuration reference](/agentic-coding-template-docs/reference/configuration/#formats).
- **Git hosting**: `target-branch`, `forge` and `forge-host` tell the pull-request skill where to go. github.com and gitlab.com receive the token without being named; a self-hosted host only after you have named it.
- **Checks**: mechanical guards that run before an action (below).
- **Logging**: `logging` and `log-level` write every agent action to `ai.log` at the project root, not versioned, handy to follow along in a second terminal.
- **Feedback**: voluntary feedback to the template author; new projects start with `feedback: confirm`, so nothing is sent without your yes. `feedback: local` makes the project never send anything to the template author: `feedback.py --send`, `--direct` and `--add` refuse, reminders never fall due, and a template bug, a hand-written `feedback: <text>` or a recurring finding becomes a backlog entry in the project instead. See [Sending feedback](/agentic-coding-template-docs/guides/feedback/).
- **Tips**: `tips` (`never`, `occasionally`, `regularly`) controls how often the session start shows a tip. Your own reminders in `docs/ai/local/reminders.md` are not affected.
- **Roles**: per-role (and per-skill) overrides of tier and reasoning, see [Tiers and reasoning](/agentic-coding-template-docs/concepts/reasoning/).

## Checks: block, warn, off

Each row of the checks table names a guard that runs before the action it describes, for example a commit, a write under `.act/`, or a worker leaving its write scope.

| Value | Effect |
| :--- | :--- |
| `block` | the action is refused |
| `warn` | the action goes ahead with a note |
| `off` | the check is skipped entirely |

A check marked in the table as "never refuses" treats `block` as `warn`. One check is different: `security-check` takes `off`, `local`, `deps` or `full`, see [The security check](/agentic-coding-template-docs/guides/security-check/).

Turning a check down is your decision. Checks such as `secret-scan` or `git-reset-hard` protect against things that cannot be undone; lower them only with a reason.

`secret-scan` holds a commit whose staged diff contains a key or token pattern. A line that carries an `act:allow-secret` comment is exempt. For a file that cannot hold comments (JSON), list the line in `docs/ai/local/secret-accepted.md` as `- <path> <hash>: <reason>`; the hold message prints the finished entry (path and a line hash, never the value). A changed line, the same line in another file, or a missing or unreadable list is held again. The override hashes that `doctor --accept` writes into `.act-lock.json` at the project root (a rule ID as key, exactly 64 lowercase hex digits as value, nothing else on the line) are not held. What each check recognises and where its limits lie is on the [checks page](/agentic-coding-template-docs/reference/topics/#checks).

`protected-watch` (`block` by default; `warn` or `off`) watches the files that [`R-safe-git-metadata`](/agentic-coding-template-docs/reference/rules/#r-safe-git-metadata) protects (git hooks and the config keys that start code, Claude settings, agents, skills and commands, `.mcp.json`, `.envrc`, `.devcontainer/**`, `.vscode/tasks.json`): after every tool call it compares them with a snapshot from the session start, so it also sees a change made by a script file or inline code that the static check `git-metadata-guard` cannot read. At `block`, a change made in a worker's call is put back at once and the changed version is kept under `.act-local/protected-watch/kept/`; a change by the orchestrator is only reported, with the command that puts the previous version back. At `warn`, every change is only reported. Claude Code's own "always allow" entries in `settings.local.json` are left alone and only reported. It reports after the call and prevents nothing; its limits are on the checks page.

`model-switch` (`warn` by default, `off` skips it; it never refuses) tells you when a worker or the session itself continues on another model, typically after the safety filter refused a request, which Claude Code does not announce in a sub-agent: at `SubagentStop` and `Stop` the orchestrator is told with its next tool call, naming the role and the models, and tells you in chat. The hook itself shows you nothing, because Claude Code records the message of these events without displaying it.

`outside-root` keeps reads and writes inside the project root and its allowed places, for the assistant and its workers alike. It starts at `block` in new projects; a project without the row runs it as `warn`. Exceptions go into `outside-root-allow`: paths relative to the project root, starting with `~` or absolute, each optionally followed by ` (read)`. An absolute entry outside the project and your home folder, such as a browser's program folder (`D:/Program Files/Browser`), is read-only like ` (read)` (one with a glob character stays writable unless ` (read)` follows it): the assistant may read and start programs below it, and the writes the check recognises are refused. A `file:` entry is ignored, and a `file:` URL in a command is read as the path it names. Both rows are described in the [configuration reference](/agentic-coding-template-docs/reference/configuration/), the rule in [`R-safe-outside-root`](/agentic-coding-template-docs/reference/rules/#r-safe-outside-root).

`docs-order` (`warn` by default) checks that the project docs stay findable under [`R-docs-order`](/agentic-coding-template-docs/reference/rules/#r-docs-order): every folder under `docs/project/` with five or more entries has a `README.md` with one line per file and subfolder. The doctor reports a missing or stale index line, a dead link and a concept that has already been decided. It also notes, without refusing, a `docs/project/` file of 300 lines or more (split it into a folder with a `README.md`) and a `docs/README.md` index line that points below a subfolder (it belongs in that folder's `README.md`). `move_doc.py` moves a document and pulls links and the index line along.

`cd-git` (`block` by default; `warn` or `off`; runs only when `tools` holds `claude-code`) refuses a Bash call that chains `cd` or `pushd` with `git`, because Claude Code asks you for approval each time for that combination, and names `git -C <folder> <command>` in a call of its own instead. `warn` names the way and lets the call pass.

`commit-hashes` (`warn` by default, `off` skips it; it never refuses) notes a commit hash in backticks that no repository knows, in a commit message or in a line added to a staged journal file. A template commit recorded in `.act-lock.json` counts as known, so the base-commit change an update journals gives no note. `commit-hashes-repos` lists further repositories to look in (`none`, or comma-separated paths such as `../agentic-coding-template`), for a journal that names commits of another repository ([`R-work-evidence`](/agentic-coding-template-docs/reference/rules/#r-work-evidence)).

`throwaway-place` (`warn` by default, `off` silences it; it never refuses) notes, in the main session only, a command or file write that puts throwaway output in the system temp directory or directly under `.act-local/`, and names `.act-local/tmp/<task-id>-<slug>/` or `.act-local/tmp/<YYYYMMDD>-<slug>/` instead ([`R-work-throwaway`](/agentic-coding-template-docs/reference/rules/#r-work-throwaway)). All three rows are in the [configuration reference](/agentic-coding-template-docs/reference/configuration/#checks).

`changelog-length` (`warn` by default, `off` skips it; it never refuses) makes `act-doctor` name an entry under `[Unreleased]` in `CHANGELOG.md` that is longer than 250 characters, with its first words.

`own-rules-budget` (default 6000 characters, `off` or `0` skips it) keeps your own rules short. `act-doctor` warns when the "Own rules" sections of `docs/ai/rules.md` and `docs/project/coding_rules.md` together exceed it, names the size and up to five lines that read like history (a date, an entry identifier, "formerly … since …"), and never blocks. The "Own rules" section of the `coding_rules.md` scaffold has a table of where each kind of rule belongs.

`act-local-tidy` keeps `.act-local/` small. At session start, at most once a day and in a background process, it removes `tmp/` entries and unknown entries directly under `.act-local/` (none that a template script creates) that are older than 7 days and whose name does not start with an open task's id, all but the newest 5 backups of `update`, and compiled-module files under `.act-local/pyc/` that belong to another Python version than the running one and are older than 7 days. The next session start reports count, size and kinds; it names only entries that could not be removed. The first run in a project only reports what it would remove; removal starts on a later day, after a session start has shown that report. `warn` only reports, `off` skips it. `act-local-keep` lists patterns relative to `.act-local/` (for example `exports, tmp/long-*`) that are never removed, or `none`. `python .act/scripts/act_local_tidy.py` shows the plan without removing anything. The rule behind it is [`R-work-throwaway`](/agentic-coding-template-docs/reference/rules/#r-work-throwaway).

### Ignore files and what the checks are not

There is no `.claudeignore`: Claude Code skips such a file without a word. Its Glob and Grep tools already leave out what `.gitignore` excludes, `node_modules` and build folders included, so the template adds no ignore file of its own. `permissions.deny` with `Read(...)` rules reaches Claude Code's own file tools, but a shell command only where its sandbox is switched on. A targeted, bounded look into a library's source (`grep -n … | head`) stays allowed; it is often how a bug in a dependency is found ([`R-work-bounded-output`](/agentic-coding-template-docs/reference/rules/#r-work-bounded-output)). Secret files are refused by `secret-read`, in shell commands too, within the limits its rule names ([`R-safe-no-secret-read`](/agentic-coding-template-docs/reference/rules/#r-safe-no-secret-read)). The checks are guard rails against mistakes, not a sandbox: neither an ignore file nor a deny rule on its own keeps an agent, or text injected into its prompt, from reading a file through the shell. That takes isolation outside the agent, such as a container or the tool's own sandbox. Which switches the tools offer for that, and where they stop, is in the [Isolation guide](/agentic-coding-template-docs/guides/isolation/).

## File and environment

`config.md` describes the **project** and is versioned. Secrets and per-machine or per-run deviations belong in the environment (for example `AGENTIC_FEEDBACK_URL` or `ACT_FORGE_API_URL`), which overrides the file for that run and never the other way round. The session start names every environment override that is active, names only, never values.

## Changing the file

`/act-config` lists every setting, `/act-config <key>` shows one with its allowed values, its default and when a change takes effect, and `/act-config <key> <value>` writes the value into that one table cell. Nothing is committed and the rest of the file stays byte for byte. In Claude Code the `UserPromptSubmit` hook answers the command; elsewhere run `python .act/scripts/config.py [<key> [<value>]]`. The Roles table is shown but edited by hand.

By hand, edit the values in the tables, not the key names or the marks (`<!-- act:... -->`): those are what the mechanism reads. An update keeps your values. `act-doctor` checks the value of every key that has a fixed list or format and reports an invalid one as `config-value`. If the project changes in a way `config.md` describes, the assistant updates it in the same step.
